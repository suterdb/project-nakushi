# ⚙ Project Nakushi -- Execution Protocol

This document defines HOW Nakushi is used in practice.

------------------------------------------------------------------------

# 1. Weekly Cycle

Every week must produce one report.

Process: 1. Review commits, PRs, issues. 2. Summarize into Done / Doing
/ Blocked. 3. Define Top 3 priorities. 4. Identify risks or debt.

If no report exists, the week did not exist.

------------------------------------------------------------------------

# 2. Decision Flow

When facing a technical or structural choice:

1.  Define the context.
2.  List at least two alternatives.
3.  Choose deliberately.
4.  Write ADR.
5.  Define rollback plan.

No rollback → no decision.

------------------------------------------------------------------------

# 3. AI Collaboration Protocol

After meaningful AI discussion:

1.  Extract 5-line summary.
2.  If decision made → create ADR.
3.  If unresolved → record as Open Question in weekly report.

Raw chat logs are never stored. Only structured conclusions are
preserved.

------------------------------------------------------------------------

# 4. Incubation Lifecycle

Idea → Incubating → Building → Validated → Spin-off → Archive

Spin-off requires at least two: - External validation - Monetization
potential - Scope expansion demand - Worth continuing beyond 4 weeks

Abandoning is allowed. Drifting is not.

------------------------------------------------------------------------

# 5. Definition of Progress

Progress = Deliberate Decisions + Validated Learning

Code volume is not progress. Busyness is not progress. Clarity is
progress.
