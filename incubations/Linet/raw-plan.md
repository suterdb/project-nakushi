# Linet — 실시간 이슈 피드 + 한 줄 커뮤니티 (업데이트, 2026-07-25)

## 서비스 개요

* **Linet**: 한 줄 형식의 텍스트 중심 피드 서비스.
* 두 개의 컨텐츠 축이 동등하게 존재하며, 동일한 UI/UX(한 줄 형식, 태그, 멘션, 리액션, 실시간 피드)를 공유한다.
  1. **이슈 피드 축**: 각 커뮤니티/컨텐츠 플랫폼에서 현재 화제가 되고 있는 주제를 자동으로 끌어와 한 줄 형태로 리스팅. 검색엔진/포털의 "실시간 검색어"와 유사한 경험.
  2. **작성 피드 축**: 기존 기획대로 사용자가 직접 한 줄 컨텐츠를 작성.
* 두 축은 탭 또는 섹션으로 구분해서 노출한다 (병합 여부·화면 구조는 이후 단계에서 확정).
* **텍스트 중심** (외부 링크 직접 노출 금지; 참고 링크는 내부 컨텐츠로 변환 후 멘션으로 참조).
* LLM을 활용한 **자동 태깅**.
* 사용자가 원할 경우 **자동완성 기반 수동 태그 입력 가능**.
* 사용자 중심 노출은 최소화하며, 태그를 중심으로 운영.
* 멘션은 **사용자가 아닌 컨텐츠**에 대해서만 가능.

## 이슈 피드 축 (신규)

* **목표**: 여러 커뮤니티·컨텐츠 플랫폼에 흩어진 "지금 화제인 것"을 한곳에서, 한 줄로 훑어볼 수 있게 한다.
* **수집 대상**: 미정 — 어떤 커뮤니티/플랫폼을 소스로 삼을지 이후 단계에서 결정.
* **수집 방식**: 미정 — 크롤링, 각 플랫폼 API, RSS, 또는 다른 방식인지 이후 단계에서 결정.
* **가공 방식**: 미정 — 원문을 LLM이 한 줄로 요약할지, 제목만 가져올지 등은 이후 단계에서 결정.
* **표시 형태**: 작성 피드와 동일한 카드 형태(`#태그 한 줄 내용 ❤️ 공감 💬 멘션 ✖️`)를 따르되, 원문 출처 표기 방식은 별도 결정 필요.
* **사용자 상호작용**: 이슈 카드에 대해 사용자가 공감(❤️)·멘션(💬)으로 반응 가능 (작성 피드와 동일한 반응 체계 재사용).

## 작성 피드 축 (기존 유지)

* 하단 고정 입력창 클릭 시 확장.
* 140자 제한 한 줄 입력.
* LLM 추천 태그 노출(자동완성 지원).
* 전송 시 피드 상단에 즉시 반영.

## 태그 및 멘션 구분

### 태그 (Tag)
* **역할**: 컨텐츠를 표현하는 주요 키워드. 이슈 피드·작성 피드 공통 적용.
* **생성**: LLM이 자동 생성하거나, 사용자가 자유롭게 입력 가능 (작성 피드), 이슈 피드는 LLM 자동 생성.
* **관리**: 내부적으로 유사 태그를 그룹화하여 관심사 기반 피드 구성에 활용.
* **활용**: 검색, 추천, 관심사 피드 구성에 사용.
* **표시**: 본문 하단에 표시.

### 멘션 (Mention)
* **형식**: `>><컨텐츠ID>`
* **대상**: 컨텐츠 단위만 가능 (사용자 멘션 불가). 이슈 카드도 멘션 대상이 될 수 있음.
* **동작**: 기본적으로 원문 비노출, **펼치기**로 확인 가능.
* **목적**: 컨텐츠 간 연결 및 참조.
* **작성**: 한 줄 규칙 내에서 멘션 포함 가능.

## 메인 피드 구성

* **목표**: "지금도 컨텐츠가 계속 생산되고 있다"는 실시간성 전달 (작성 피드·이슈 피드 공통 목표).
* 최신순 피드가 기본이며, 신규 컨텐츠를 상단에 자연스럽게 추가 (갱신 주기는 축마다 다를 수 있음 — 이슈 피드는 외부 소스 갱신 주기에 종속).
* 채팅처럼 급격히 올라가지 않고, 읽기 좋은 속도로 부드럽게 업데이트.
* 각 줄은 다음과 같은 형태:

  ```
  #태그 한 줄 내용  ❤️ 12  💬 3  ✖️
  ```

  * **❤️**: 클릭 시 공감(숫자 증가, 애니메이션 효과)
  * **💬**: 클릭 시 해당 컨텐츠를 멘션하는 입력창 오픈
  * **멘션 숫자**: 클릭 시 멘션된 컨텐츠 목록 표시
  * **✖️(X 버튼)**:
    * **작성자**: 오리지널 컨텐츠 삭제 (이슈 카드는 작성자가 없으므로 해당 없음)
    * **소비자**: 해당 컨텐츠를 자신의 피드에서만 숨김

## 태그 탐색

* 태그 클릭 시 해당 태그 기반 피드 필터링 (이슈 피드·작성 피드 통합 또는 분리 여부는 미정).
* 태그 검색 및 자동완성 제공.

## 리액션

* ❤️ 클릭 시 공감수 증가 (애니메이션).
* 재클릭 시 취소 가능.

## UI 및 인터랙션 플로우 시안

### 메인 피드 화면

* 화면 전체를 피드로 구성, 상단 GNB 없음.
* 각 컨텐츠 카드: `#태그 내용 ❤️ 공감수 💬 멘션수 ✖️`
* 태그 클릭: 해당 태그 기반 필터링 피드로 이동.
* ❤️ 클릭: 즉시 공감 반영 + 애니메이션.
* 💬 클릭: 해당 컨텐츠 멘션 작성창 팝업.
* 멘션 숫자 클릭: 멘션된 컨텐츠 목록 표시.
* ✖️ 클릭:

  * 작성자: 원본 컨텐츠 삭제 (이슈 카드는 해당 없음)
  * 소비자: 해당 컨텐츠를 자신의 피드에서 숨김

### 실시간 업데이트 방식

* 페이지 진입 시 최신 컨텐츠 로드.
* 작성 피드는 5초 주기 신규 컨텐츠 로드 → 상단 부드럽게 추가. 이슈 피드의 갱신 주기는 외부 소스 특성에 따라 별도 결정.
* 스크롤 위치 고정, 읽는 흐름 방해 최소화.

### 작성 및 멘션 플로우

* 하단 고정 입력창 → 클릭 시 확장.
* 멘션 클릭 시 자동으로 멘션 코드 포함.
* 등록 시 피드 상단에 즉시 반영, 원글 멘션 수 갱신.

## 링크 처리 정책

* **외부 링크 직접 노출 금지**.
* **참고 링크는 내부 컨텐츠로 변환 후 멘션으로 참조**.
* **유해 URL 필터링** 및 **중복 방지**.
* **외부 원문 비노출 원칙**. 단, 이용자 편의를 위해 원문 제목 또는 간략한 메타 정보(예: 페이지 타이틀)를 함께 제공.
  * HTML `<title>`만 단순 노출하는 방식은 지양.
  * LLM 요약은 비용 문제로 상시 적용하지 않음.
  * 향후 필요 시 선택적 요약 기능 제공 가능.
  * (이슈 피드 축의 원문 출처 표기 방식도 이 정책 범위 내에서 이후 결정)

## 미결정 사항 (다음 단계에서 확정 필요)

* 이슈 피드의 수집 대상 플랫폼/커뮤니티
* 이슈 피드의 수집 방식 (크롤링 / API / RSS 등)
* 이슈 피드의 가공 방식 (LLM 요약 여부, 원문 링크 처리)
* 이슈 피드와 작성 피드의 화면 구조 (탭 분리 vs 통합 피드)
