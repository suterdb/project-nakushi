# Problem Definition — Pantry

## Who

고물가 시대에 직접 요리를 시도하는 1인·2인 가구. 특히 냉장고에 재료가 있지만 레시피와 완전히 일치하지 않아 요리를 포기하거나, 불필요한 재료를 추가 구매하는 사람.

## What

기존 레시피 서비스는 "레시피를 전달"하는 데 그친다. 사용자가 실제로 필요한 것은 **"내가 가진 재료로 이 레시피를 만들 수 있는가"** 에 대한 판단이다. 어떤 재료가 필수인지, 무엇으로 대체할 수 있는지, 무엇을 생략해도 되는지를 알려주는 서비스가 없다.

## Why now

- 고물가로 인해 외식 대신 자취 요리 수요 증가
- AI(LLM)의 요리 도메인 이해도가 충분히 높아져 재료 분류 작업이 실현 가능해짐
- 경량 모델(Haiku급)의 비용 효율로 소규모 서비스에서도 AI 기능 탑재 가능

## Root cause

레시피 서비스는 콘텐츠 소비 플랫폼으로 설계되어 있다. 개인화(내 재료 기반 변주)는 서비스 구조상 추가하기 어렵고, 기존 사업 모델(광고, 조회수)과 맞지 않는다. 결국 사용자는 스스로 레시피를 변환해야 하지만, 요리 지식이 부족하면 이를 수행하기 어렵다.

## Success definition

- 경량 AI 모델만으로 재료 분류(필수/대체/생략) 품질이 "쓸만한 수준"임을 확인한다.
- 실제 사용자가 레시피 변환 결과를 보고 요리를 실행한 사례가 발생한다.
- 재료 낭비 없이 요리에 성공했다는 피드백을 최소 3건 이상 확보한다.
