# Raw Plan — Pantry

> 내 냉장고 속 재료로, 내 상황에 맞는 요리를 — 개인화 레시피 어시스턴트

---

## 1. 문제 정의

### 배경

고물가 시대에 1인·2인 가구를 중심으로 직접 요리에 대한 필요성이 높아지고 있다.
예능 프로그램을 통해 셰프 직업에 대한 관심도는 올라갔으나, 실제로 제공되는 가치는 '레시피 전달' 수준에 머무른다.

### 핵심 통찰

요리에 대한 실질적인 이해도는 **레시피를 내 상황에 맞게 변주(adapt)할 수 있는 능력**으로 측정된다.
이는 곧 재료에 대한 다음의 이해를 포함한다:

- 필수 재료 vs. 선택 재료
- 생략 가능한 재료 (셰프의 킥 등)
- 대체 가능한 재료
- 추가해봄직한 재료

현재 시중의 레시피 서비스는 이 개인화 레이어를 제공하지 않는다.

---

## 2. 솔루션 개요

사용자가 현재 보유한 재료를 등록해두면, 특정 레시피를 기준으로:

- 지금 당장 요리 가능한지 여부 판단
- 필수 구매가 필요한 재료 안내
- 보유 재료로 대체 가능한 항목 제안
- 생략 가능한 재료 컨펌 요청 (유저 인터랙션)
- (추후) 현재 재료 기반의 레시피 추천

AI를 통해 이 모든 분석을 제공하되, **경량 모델 + 프롬프트 튜닝**으로 '쓸만한 수준'을 확보하는 것이 핵심 기술 과제다.

---

## 3. MVP 정의

### 목표

> 경량 AI 모델과 프롬프트 튜닝만으로 유의미한 재료 분석이 가능한가를 검증한다.

### 핵심 기능

| 기능 | 설명 |
|------|------|
| 재료 등록 | 사용자가 현재 보유한 소스류, 냉장고 재료 등을 직접 입력 |
| 레시피 입력 | 직접 입력 또는 AI 검색을 통해 레시피 수급 |
| 재료 분석 | AI가 레시피 재료를 필수/대체/생략 가능 항목으로 분류 |
| 구매 리스트 생성 | 보유하지 않은 필수 재료 목록 제공 |
| 생략 컨펌 | 생략 가능 재료에 대해 유저 확인 후 최종 변환 레시피 제공 |

### 제외 범위 (MVP 이후)

- 회원제 / 인증
- 재료 잔량 추적
- 레시피 히스토리 저장
- 추천 레시피 피드

---

## 4. Post-MVP 로드맵

### 4-1. 재료 관리 고도화

- 회원제 도입 → 재료 데이터 RDBMS 영구 저장
- 다양한 재료 등록 방식 지원:
  - 직접 입력
  - 오프라인 마트 영수증 스캔 (OCR + AI 파싱)
  - 온라인 주문 인보이스 스크린샷 파싱
- 잔량 추적: 레시피 사용 기록 기반으로 잔량 추산 (현실적 한계 존재, 정확도 이슈 인지)

### 4-2. 개인화 레시피 피드

- 홈 화면에서 현재 보유 재료 기반 추천 레시피 노출
- 초기에는 AI 추천, 재료 변동이 없으면 캐싱 처리로 비용 절감

### 4-3. 비즈니스 모델

| 모델 | 내용 | 검토 상태 |
|------|------|-----------|
| 쇼핑 링크 제휴 | 필수 구매 재료에 특정 쇼핑몰 구매 링크 제공 → 브릿지 수익 | 실현 방안 별도 검토 필요 |
| 구독제 | AI 사용량이 유의미한 비용이 될 경우 유료 회원제 도입 | AI 비용 구조 검토 후 판단 |

## 5. 기술 고려사항

### AI 전략

- **경량 모델 우선**: Haiku급 모델 사용을 기본 전제로 설계
- **프롬프트 튜닝이 핵심**: 재료 분류(필수/대체/생략)의 품질은 시스템 프롬프트 설계에 달려 있음
- **시스템 프롬프트에 재료 컨텍스트 주입**: 사용자 보유 재료를 매 요청마다 프롬프트에 포함

### 데이터 구조 (초안)

```
User
 └── Ingredients (보유 재료 목록)
 └── RecipeHistory (변환된 레시피 히스토리)

Recipe
 └── OriginalIngredients
 └── TransformedIngredients (필수/대체/생략 분류 결과)
```

### 잔량 추적 이슈

레시피 실행 후 재료 잔량을 자동으로 감산하는 방식은 현실적 싱크 문제가 있음.
MVP에서는 잔량 추적을 제외하고, 추후 UX 설계와 함께 재검토.
